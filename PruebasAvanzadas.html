Programación Orientada a Pruebas

Pruebas Avanzadas e Integración Continua (CI)

Del Aislamiento Local a la Automatización Total en la Nube

"Un software de calidad no solo funciona en la máquina del desarrollador; se comprueba y valida de forma autónoma en cada cambio."

1.¿Por qué necesitamos Pruebas Avanzadas?

Hasta ahora hemos dominado las pruebas unitarias puras y mocks (aislando cada clase para probar su lógica independiente). Sin embargo, en el mundo real surgen preguntas críticas:

  • ¿Qué pasa cuando el controlador HTTP recibe una petición real y debe interactuar con el servicio?
  • ¿Cómo aseguramos que las rutas, las validaciones de JSON y los códigos de estado HTTP responden correctamente?
  • ¿Cómo evitamos que dependencias externas rompan el sistema sin darnos cuenta?

Pruebas Unitarias

Prueban una sola clase o método de forma aislada utilizando Mocks. Son ultra rápidas pero no validan la comunicación entre componentes.

Pruebas de Integración (Avanzadas)

Verifican que múltiples piezas del sistema (Controlador + Servicio + Contexto Web) colaboren de manera fluida y sin fricciones.

2. Pruebas de Integración con Spring Boot y MockMvc

Para probar controladores web sin necesidad de levantar un servidor físico pesado (como Tomcat en el puerto 8080), utilizamos MockMvc. Esto simula peticiones HTTP dentro del contexto real de Spring.

Ejemplo Práctico: Probando un Endpoint REST

// Archivo: src/test/java/com/empresa/app/ReporteControllerIntegrationTest.java
package com.empresa.app;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;

@SpringBootTest // Levanta el contexto completo de Spring Boot
@AutoConfigureMockMvc // Configura el simulador HTTP
class ReporteControllerIntegrationTest {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void testGenerarReporteEndpointExitoso() throws Exception {
        mockMvc.perform(post("/api/reportes")
                .param("tipo", "PDF")
                .param("datos", "Ventas Q3")
                .contentType(MediaType.APPLICATION_JSON))
                .andExpect(status().isOk()) // Valida HTTP 200
                .andExpect(jsonPath("$.estado").value("EXITOSO")); // Valida respuesta JSON
    }
}

3. Integración Continua (CI): El Guardián en la Nube

¿De qué sirve tener excelentes pruebas unitarias y de integración si dependen de que el desarrollador recuerde ejecutarlas manualmente antes de subir el código?

¿Qué es la Integración Continua?

Es una práctica de ingeniería donde los desarrolladores fusionan su código en un repositorio central (como GitHub) de manera frecuente. Cada fusión o cambio activa automáticamente un servidor virtual en la nube que descarga el proyecto, compila las dependencias y ejecuta todas las pruebas.

El Problema sin CI

"En mi máquina sí funcionaba". Los errores se descubren tarde, cuando las ramas ya están combinadas y el sistema colapsa en producción.

La Solución con CI (Fail Fast)

Si un test falla, GitHub bloquea el cambio inmediatamente. Nadie puede integrar código defectuoso al equipo.

4. Automatización con GitHub Actions (Paso a Paso)

GitHub Actions es la herramienta nativa de GitHub para crear flujos de trabajo automatizados. Para que la nube compile tu proyecto y ejecute las pruebas automáticamente, solo necesitas crear un archivo de configuración YAML.

¿Dónde se aloja el archivo?

En la raíz del repositorio local (en tu IDE), debes crear exactamente esta estructura de carpetas:

tu-proyecto/
├── .github/
│   └── workflows/
│       └── maven.yml    <-- ¡El archivo de automatización vive aquí!
├── src/
├── pom.xml
└── ...

Código de configuración (`maven.yml`)

# Nombre del Pipeline
name: Java CI with Maven

on:
  push:
    branches: [ "main", "master" ]
  pull_request:
    branches: [ "main", "master" ]

jobs:
  build:
    runs-on: ubuntu-latest # Servidor virtual Linux en la nube

    steps:
    - uses: actions/checkout@v4 # Descarga el código del repositorio
    
    - name: Set up JDK 21
      uses: actions/setup-java@v4
      with:
        java-version: '21'
        distribution: 'temurin'
        cache: maven

    - name: Build and Test with Maven
      run: mvn clean verify # Compila y ejecuta pruebas unitarias y de integración

5. Actividad Práctica Integradora: Desde Cero

Para consolidar todo lo visto, por favor lleven a cabo el siguiente ejercicio práctico en equipos de 2 integrantes. Recuerden colocar en un documento Word o PDF toda la evidencia de su actividad y en la portada el nombre de ambos integrantes (Es importante que cada uno suba a plataforme el trabajo)

1 Paso 1: Preparación del Repositorio

Creen un proyecto en Spring Boot que gestione una funcionalidad básica (ej. el cotizador de envíos o la gestión de inventario aplicando SOLID).

2 Paso 2: Escritura de Pruebas Unitarias con Mocks

Aseguren que la lógica de negocio esté probada unitariamente usando Mockito, aplicando TDD (Red-Green-Refactor).

3 Paso 3: Creación de la Prueba de Integración

Añada una prueba utilizando `SpringBootTest` y `MockMvc` para validar que el controlador HTTP responde correctamente a los requerimientos de negocio.

4 Paso 4: Configuración del Pipeline de CI

Creen la carpeta `.github/workflows/` y añadan el archivo `maven.yml`. Realicen un commit local y hagan `git push` hacia su repositorio en GitHub.

5 Paso 5: Verificación del Resultado

Ingresen a la pestaña "Actions" de su repositorio en GitHub y verifiquen que la palomita verde confirme que el servidor en la nube compiló y pasó todas las pruebas con éxito.
